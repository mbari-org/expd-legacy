ROVCTD Data Quality Flag Management

The ROVCTD quality flags are maintained by the sensor technician.

When the data is automatically loaded by the nightly processing scripts, the flag values are set to the default of 2.  As the sensor technician and scientists validate the data the flags should be updated to indicate their level of quality. Data users should contact the sensor technician to apply changes to the quality flags.

The sensor technician (who has change privileges in the database) uses the change_flag stored procedure to update quality flag values. The Query Analyzer tool, one of the Microsoft SQL Server 7.0 client tools, is a way to run this procedure. The change_flag stored procedure is used with the following arguments.  Note: all of the arguments are required.

Usage:

    change_flag 'rovname', 'flagname', newvalue, 'start date time', 'end date time'

Example:

    change_flag 'vnta', 'depthFlag', 3, '05/15/1999', '05/16/1999'

Acceptable values:

rovname: vnta, tibr

flagname: rovCtdDtgFlag, presFlag, temperFlag, latFlag, lonFlag, depthFlag, salinFlag, thetaFlag, oxygFlag, lightFlag, beacFlag, soundFlag, sigmathetaFlag

newvalue: 0,1,2,3,4

Calculated flags:

The values of some data are calculated from other data.  The quality flags of the calculated values cannot be set higher than the quality flags of the data that they are calculated from.  An SQL trigger enforces this rule by immediately changing the flag of a calculated value to the lowest flag of the data it depends on if it is accidentally set too high.
